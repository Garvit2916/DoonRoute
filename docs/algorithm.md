# Algorithm

DoonRoute solves shortest-distance routing on a directed road graph. The only
cost is edge length in metres. Both implementations use Dijkstra's algorithm and
are expected to return the same shortest path distance.

## Graph model

`src/graph_loader.py` loads `data/raw/dehradun_drive.graphml` with NetworkX. The
loader flattens the graph into indexed adjacency lists:

```text
adjacency[i] = [(j, length_m), ...]
```

Parallel edges are retained in the loader's edge-attribute map, while the binary
routing representation keeps the smallest length for each directed node pair.
Node indices are contiguous integers assigned during loading. OSM node IDs are
preserved separately.

The real network has 28,248 nodes, 64,912 directed edges, and 17,804 valid
intersections.

## Intersections

A graph node is a valid intersection when either condition holds:

1. Its undirected road degree is at least three.
2. Its OSM `junction` tag is present and is not `no` or `false`.

The first condition handles ordinary road forks and crossings. The second
handles tagged junctions that may have a lower graph degree after OSM
simplification.

`SpatialIndex` projects intersection coordinates into a local metre plane using
an equirectangular approximation around the mean latitude. A SciPy `cKDTree`
answers nearest-intersection queries efficiently. The returned snap distance is
the distance in the projected plane, which is accurate enough for urban snapping
and is reported to the caller.

## Random points

`generate_random_points` samples latitude and longitude uniformly inside the
graph bounds using a seeded `random.Random`. Each sample is snapped to the
nearest valid intersection. Sampling is retried up to `max_attempts_per_point`
times per point. If no intersection is within `max_snap_distance_m`, the
function raises an error instead of silently producing fewer points.

With a fixed seed, the generated points are reproducible.

## Python Dijkstra

`PythonDijkstra` uses a binary heap and lazy deletion:

```text
dist[source] = 0
push (0, source)
while heap:
    pop smallest tentative distance
    skip stale entries
    for each outgoing edge:
        relax target if the new distance is smaller
```

The result contains:

- shortest distance
- node path
- visited count
- relaxation count
- source and target metadata

The implementation rejects negative edge weights and handles disconnected
targets by returning an unreachable result.

## Cython Dijkstra

`src/cython_dijkstra.pyx` is independent of the Python solver. It loads the
binary graph generated by `write_binary_graph` into contiguous C arrays:

```text
offsets[0..n]   CSR row boundaries
targets[0..m-1] destination node indices
weights[0..m-1] edge lengths in metres
```

The search core:

- allocates typed C arrays for distances, parents, and visited flags
- uses a C binary min-heap
- breaks equal-distance ties by node index for deterministic paths
- runs the relaxation loop with the GIL released
- reconstructs the path only after the native search returns

The extension is built as a C extension from Cython-generated C. No C++ source
or C++ standard-library container is used.

## Waypoint routing

`route_waypoints` solves each leg independently:

```text
start -> waypoint 1 -> waypoint 2 -> ... -> destination
```

The combined path drops the duplicate boundary node between consecutive legs.
Every consecutive pair in the final path is checked against the loaded
adjacency, so a corrupted or mismatched leg cannot be silently combined.

The combined distance is the sum of leg distances and is independently
recomputed from the edge weights.

## JSON export

`build_route_document` records:

- dataset metadata
- algorithm name and execution time
- source, destination, and ordered waypoints
- original and snapped coordinates with snap distances
- per-leg paths, node IDs, coordinates, and distances
- combined path and total distance
- optional benchmark metadata

`write_route_json` writes UTF-8 JSON, and `load_route_json` reads it back for
round-trip validation.

## Complexity

For `V` nodes and `E` directed edges, the heap-based search is:

```text
time:  O((V + E) log V)
space: O(V + E)
```

The Cython version has the same asymptotic complexity but lower interpreter and
heap overhead, which is why it is faster on the real network.
